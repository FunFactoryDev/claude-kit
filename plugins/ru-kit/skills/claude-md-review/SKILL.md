# Ревью CLAUDE.md

Проверь файл: $ARGUMENTS (если путь не указан, бери `./CLAUDE.md`). Отвечай по-русски.

Исходная мысль: `CLAUDE.md` загружается в контекст в каждой сессии, поэтому каждая строка либо приносит пользу, либо тратит токены на каждом ходу. Большинство случаев «модель не слушается» - это проблемы самих инструкций.

## Шаги

1. Прочитай файл. Если в проекте есть вложенные `**/CLAUDE.md` или `~/.claude/CLAUDE.md`, учти и их: они тоже попадают в контекст.
2. Оцени каждое измерение ниже и процитируй конкретные строки, которые не проходят.
3. Выведи отчёт по формату внизу. Предлагай готовые формулировки, а не «сделай конкретнее».

## Что проверять

**Конкретность** - самое важное.
- Отмечай непроверяемые правила: «пиши чистый код», «следуй лучшим практикам», «будь аккуратен».
- Каждое правило должно проверяться чтением диффа. «Разбивай функции длиннее 40 строк» проверяется; «пиши короткие функции» - нет.

**Именованные якоря.**
- Правила про «конфиг», «наш API-слой», «обычный паттерн» заставляют каждый раз искать заново. Замени их реальными путями: `src/config/env.ts`, `src/api/client.ts`.
- Проверь, что каждый упомянутый путь, команда и файл существуют. Мёртвые ссылки перечисли: `CLAUDE.md`, указывающий на удалённый файл, вводит в заблуждение.

**Устаревание.**
- Версии, имена моделей и команды, которые больше не совпадают с репозиторием.
- Инструкции для фреймворка, скрипта или папки, которых уже нет.
- Сверь команды сборки, тестов и линтера с `package.json`, `Makefile`, `pyproject.toml` или аналогом: неверная команда тестов хуже, чем никакой.

**Раздутость.**
- Всё, что можно узнать из самого кода: дерево файлов, список зависимостей, пересказ функций. Claude умеет читать репозиторий.
- Длинные процедуры для редкой задачи: им место в скилле, который загружается только при вызове.
- Общие советы, верные для любого проекта, ничего не говорят про этот.

**Противоречия.**
- Правила, которые спорят друг с другом или с тем, что делает код. Покажи обе стороны и спроси, что главнее.
- Неожиданный приоритет: вложенный `CLAUDE.md` или `~/.claude/CLAUDE.md` перекрывает то, что автор ожидал.

**Чего не хватает** (если этого нет):
- Как запустить тесты, сборку и линтер - всё, что нужно, чтобы проверить свою правку.
- Неочевидные ограничения: папка, которую нельзя трогать, генерируемый файл, обязательный шаг миграции.
- Соглашения, которые удивляют и не видны при беглом чтении кода.

## Формат отчёта

```
## Ревью CLAUDE.md - <путь> (<N> строк)

**Вердикт:** <одно предложение>

### Блокирует
- L<n>: <цитата> -> <готовая замена>

### Стоит исправить
- L<n>: <цитата> -> <готовая замена>

### Удалить (тратит контекст в каждой сессии и ничего не даёт)
- L<n>-<m>: <что и почему>

### Не хватает
- <пробел> -> <строка, которую стоит добавить>

**Размер после правок:** примерно <N> строк (было <M>)
```

## Правила

- Цитируй реальные номера строк и реальный текст. Не выдумывай находки, чтобы заполнить раздел.
- Если в разделе нет находок, пиши `Нет.` Чистый файл - нормальный результат.
- Удалять лучше, чем переписывать. Лучший `CLAUDE.md` достаточно короткий, чтобы его читали.
- Не редактируй файл, пока тебя об этом не попросят. Сначала отчёт.
